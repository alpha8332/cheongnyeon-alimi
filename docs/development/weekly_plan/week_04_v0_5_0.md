## 목표

공식 HTTPS Source 수집, 지역 고유 청년정책 수집·중복 제외, 핵심 신청 조건
요약, 추천, 즐겨찾기, D-Day·내부 알림·캘린더와 관리자 기능의 계약을 고정하고
실제 PostgreSQL → FastAPI → React 흐름으로 모두 연결한다. 4주차는 `v0.5.0`
tag를 만드는 주차는 아니지만,
설계한 기본 기능을 5주차로 이월하지 않고 구현과 담당자 자체 검증까지 끝낸다.

보고서 대조, 독립 사용성 리뷰와 QA 수행은 4주차 완료 조건에서 제외한다.
이 역할들은 5주차 추가 기능·오류 수정·UI/UX 최적화와 담당자 자체 회귀가
끝난 뒤 수행하되,
`v0.5.0` 최종 Gate와 tag보다 먼저 완료해야 한다.

#### Gate W4-G0 - 계약 승인

- 일반 사용자 계정 제외와 localStorage 저장 경계가 확정됨
- 관리자 화면은 아이디 없이 숫자 4자리 PIN 한 칸만 사용함
- 최초 `0000`은 development·localhost에서만 허용하고, 배포는 명시적 PIN
  hash·별도 token secret이 없으면 fail-closed함
- 짧은 token 수명·역할·반복 실패 rate limit과 `401`·`403`·`429`가 확정됨
- Frontend의 로그인·토큰 보관·로그아웃 책임이 확정됨
- 추천 점수·이유·제외·미확정 조건과 자격 비확정 의미가 확정됨
- 공식 HTTPS Source 한 곳, 허용 경로·요청 빈도·보존 범위가 확정됨
- 필수·제외·우대·서류·확인 필요와 항목별 evidence 계약이 확정됨
- 개인 비교는 `조건상 일치`·`조건상 불일치`·`추가 확인 필요`만 사용하고
  최종 자격을 단정하지 않음
- D-Day·내부 알림·`.ics`의 KST·날짜 미상 규칙이 확정됨
- 수동 실행 `202`·run ID·중복·stale와 품질 오류 노출이 확정됨
- 관리자 DB 화면은 승인 Policy projection 읽기 전용이며 arbitrary SQL과
  데이터 수정·삭제가 범위 밖임
- file log directory·format·component level·rotation·retention·redaction과
  request·run·source correlation이 확정됨
- 회전 archive만 확인 절차 뒤 삭제하고, 현재 로그는 rotate 후 정리하며 path
  containment·활성 handle 보호·별도 감사 기록을 요구함
- Data·Backend·Frontend가 각 소비 초안을 검토함

모두 충족하면 Team Leader가 `W4-G0_APPROVED`를 기록한다. 미확정 사항이
구현을 막으면 담당·선택지·재개 조건을 기록하고 구현을 시작하지 않는다.

#### Gate W4-G4 - midpoint 판정

Team Leader는 담당자 자체 검증과 실제 세 E2E를 기준으로 다음 중 하나를
기록한다.

- `W4-G4_MIDPOINT_PASS`: 설계한 모든 기본 기능 구현·연결 완료, 5주차 추가
  기능·오류 수정·UI/UX 최적화와 독립 검증 가능
- `W4-G4_CONDITIONAL`: 기본 기능은 모두 구현됐지만 비차단 검증 제약이나 낮은
  위험 결함의 담당·완료 조건이 명확함
- `W4-G4_BLOCKED`: 실제 연결 또는 필수 계약이 실패해 5주차 검증 착수 불가

추천, 즐겨찾기, D-Day, 내부 알림, `.ics`, 관리자 실행·데이터 표·영속 로그,
공식 웹 Source와 핵심 신청 조건 중 하나라도 미구현이면 `MIDPOINT_PASS`나
`CONDITIONAL`이 아니라 `BLOCKED`다.

보고서·사용성 리뷰·QA가 아직 수행되지 않았다는 사실은 이 Gate에서 숨기지
않는다. W4-G4는 Release 2 최종 Gate가 아니며 `v0.5.0` tag 근거로 사용할 수
없다.

## 인계사항 발생 조건

다음 실제 차단이 발생할 때만 `docs/index.md` 공동 인계 보드에 등록한다.

- 관리자 인증 방식이 Backend 04 또는 Frontend 03 구현을 막음
- CollectionRun 상태·동시 실행 계약이 Data·Backend에서 다르게 해석됨
- 추천 DTO·이유·미확정 조건의 Backend·Frontend 소비가 충돌함
- 웹 Source의 identity·이용 조건·HTML 구조가 승인 계약과 충돌함
- 자격요건 Schema·API·UI의 partial·evidence 의미가 다르게 해석됨
- 관리자 데이터 projection이나 로그 redaction·삭제 감사 계약이 영역별로 충돌함
- 품질 통계가 Raw·credential·내부 예외를 노출해야만 구현 가능함
- Schema·Migration 변경 없이는 반복 수집·수정 감지를 구현할 수 없음
- 실제 E2E가 다른 담당 Forest 변경 없이는 진행되지 않음

미래 계획 자체나 5주차 독립 검증 예정은 활성 인계사항으로 등록하지 않는다.
