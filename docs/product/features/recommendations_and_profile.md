# 맞춤 추천과 프로필

## 기능 목적

사용자가 매번 같은 지역, 연령과 관심 분야를 다시 입력하지 않아도 자신과 관련
있는 정책을 우선 확인하게 한다. 추천은 설명 가능한 규칙으로 순서를 정하며,
신청 자격이나 선정 가능성을 확정하지 않는다.

## 사용하는 화면

| 화면 | 주소 | 역할 |
| --- | --- | --- |
| 프로필 | `/profile` | 거주지역·만 연령·복수 관심 분야 저장 |
| 맞춤 추천 | `/recommendations` | 조건 편집, 추천 결과와 이유 확인 |
| 홈 | `/` | 저장 프로필이 있을 때 추천 정책 일부 표시 |
| 정책 목록 | `/programs` | 검색 후보 안에서 프로필 선호도 보정 |

## 프로필에 저장하는 정보

- 거주지역
- 만 연령
- 복수 관심 분야

이름, 계정 ID, 주민등록번호, 전화번호, 이메일과 소득·자산 정보는 프로필 입력
대상이 아니다. 관심 분야는 하나가 아니라 여러 개를 선택할 수 있고, 중복 값은
제거한 뒤 선택 순서를 보존한다.

## 저장 원리

프로필은 서버 계정이 아니라 현재 브라우저 `localStorage`의 versioned 사용자
데이터에 저장된다.

```text
프로필 form
→ 입력 trim·연령 범위·분야 중복 검증
→ versioned localStorage payload
→ 홈·추천·검색이 같은 snapshot 구독
```

저장 내용이 실제로 바뀐 경우에만 새 snapshot을 만들고 구독 화면을 갱신한다.
지원하는 이전 Schema는 현재 형식으로 이동하며, 손상됐거나 알 수 없는 버전은
안전한 기본값으로 복구하고 사용자에게 복구 사실을 알린다.

프로필은 다른 브라우저나 PC와 동기화되지 않으며 Backend DB에 사용자 row를
만들지 않는다.

## 추천 요청 원리

추천은 지역, 연령, 관심 분야, 신청 상태와 품질 포함 여부를 Backend에 전달한다.
일반 사용 환경에서는 이 요청이 사용자의 PC에서 실행 중인 로컬 Backend로만
전달되고 원본 정책 Source로 전송되지 않는다.

후보는 활성 공개 dataset 중 공개 생명주기 조건을 통과한 정책으로 제한한다.
기본 추천은 마감 정책과 `invalid` 정책을 포함하지 않는다.

## 추천 판정 원리

각 정책은 요청된 차원마다 `match`, `mismatch`, `unknown`에 해당하는 의미로
평가된다.

### 관심 분야

복수 관심 분야 중 하나 이상이 정책의 전체 `categories`와 일치하면 분야 후보가
된다. 정책에 분야가 확인됐지만 모두 불일치하면 후보에서 제외한다. 대표 분야
하나만 비교하지 않는다.

### 지역

선택한 지역의 직접 정책, 상위 관할, 하위 관할과 전국 정책을 행정구역 계층과
지역 rule에 따라 평가한다. 다른 지역으로 확정되면 제외하고, 지역 근거가 없으면
전국으로 추정하지 않은 채 미확정 후보로 남긴다.

### 연령

최소·최대 연령이 확인되면 사용자의 만 연령과 비교한다. 범위를 벗어나는 확정
불일치는 제외하고, Source placeholder나 조건 누락은 미확정으로 처리한다.

### 신청 상태

현재 모집 중인 정책에 상태 근거를 부여한다. 종료일이 한국 표준시 오늘보다
과거인 정책과 inactive 정책은 추천 전에 공개 후보에서 제외한다.

## 추천 점수와 순서

현재 기본 점수는 관심 분야, 지역, 연령 일치에 각각 주요 점수를 부여하고 현재
신청 가능 상태를 추가 반영한다. 점수 자체보다 다음 원칙이 중요하다.

- 확정 불일치 조건을 점수로 덮어 후보에 남기지 않는다.
- 미확정 조건을 확정 일치로 계산하지 않는다.
- 같은 점수에서는 정책 ID를 사용해 결과 순서를 결정적으로 유지한다.
- 추천 점수는 수혜 확률이나 자격 충족 비율이 아니다.

## 추천 이유

각 결과는 점수만 보여주지 않고 사람이 이해할 수 있는 이유를 제공한다.

- 거주지 조건 부합
- 연령 조건 부합
- 관심 분야 부합
- 현재 신청 가능 상태
- 프로필 선호도와 관련된 검색 순위 보정

자동 확인할 수 없는 조건은 `unknown_conditions`로 분리한다. 모든 추천 응답은
실제 자격을 확정하지 않는다는 안내를 함께 제공한다.

## 홈 추천과 검색 우선순위

### 홈

저장 프로필이 하나라도 있으면 홈은 같은 추천 API를 사용한다. 프로필이 없으면
마감·접수 예정·지난 마감일을 제외한 공개 정책을 안전한 기본 후보로 보여준다.

### 자연어 검색

프로필은 사용자가 검색창이나 filter에서 명시한 지역·연령·분야를 덮지 않는다.
검색 조건이 후보 집합을 결정하고, 프로필은 그 후보 안에서 관련도와 이유만
보정한다. 예시 검색은 프로필 강제 적용을 끄고 모든 사용자에게 같은 예시 결과를
보여준다.

## 빈 결과와 오류

- 모든 조건이 확정 불일치면 빈 추천 결과를 반환한다.
- 빈 결과는 서버 오류와 구분해 조건 변경을 안내한다.
- 연령 범위, 분야 개수와 결과 limit이 계약을 벗어나면 `422`로 거부한다.
- 서버 오류는 재시도 가능한 상태로 표시한다.
- 미확정 조건이 있다는 이유만으로 결과 전체를 오류 처리하지 않는다.

## 개인정보와 보안

- 프로필은 현재 브라우저에만 저장한다.
- 추천 요청에는 이름·연락처·정밀 주소가 없다.
- 조건은 로컬 Backend에만 전달하고 외부 Source에 전달하지 않는다.
- 로그에 프로필 request body 전체를 기록하지 않는다.

## 현재 제한사항

- 사용자 계정과 클라우드 동기화가 없다.
- 사용자가 브라우저 데이터를 삭제하면 프로필을 복구할 수 없다.
- 소득·자산·가구 등 입력하지 않은 조건은 개인화 판정할 수 없다.
- 규칙 기반 추천이며 개인의 실제 선정 결과를 학습하는 모델이 아니다.
- 공개 dataset snapshot보다 최신인 원문 변경을 자동 반영하지 않는다.
