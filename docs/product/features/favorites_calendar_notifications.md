# 즐겨찾기·달력·알림

## 기능 목적

검색 중 발견한 정책을 다시 찾을 수 있게 저장하고, 신청 시작일과 마감일을 일정
관점에서 확인하게 한다. 계정 없이 사용할 수 있도록 모든 개인 데이터는 현재
브라우저에만 둔다.

## 사용하는 화면

| 기능 | 화면 | 주소 |
| --- | --- | --- |
| 즐겨찾기 추가·제거 | 정책 카드·상세 | `/`, `/programs`, `/programs/{id}` 등 |
| 즐겨찾기 관리 | 즐겨찾기 | `/favorites` |
| 일정 확인 | 달력 | `/calendar` |
| 마감 확인 | 알림 | `/notifications` |

## 즐겨찾기 저장 원리

즐겨찾기는 정책의 공개 숫자 ID와 폴더 ID를 versioned `localStorage` payload에
저장한다. 정책 본문 전체를 복사하지 않고 현재 공개 API에서 정책을 다시 조회한다.

```text
정책 카드·상세의 북마크 동작
→ 정책 ID와 대상 폴더 저장
→ localStorage snapshot 변경 알림
→ 즐겨찾기·달력·알림 화면 동시 갱신
```

같은 정책을 같은 폴더에 중복 저장하지 않는다. 내용이 바뀌지 않은 저장 동작은
불필요한 snapshot 갱신을 만들지 않는다.

## 폴더 원리

- 최초 상태에는 삭제할 수 없는 기본 폴더가 있다.
- 사용자는 이름이 있는 새 폴더를 만들 수 있다.
- 정책을 선택한 폴더에 저장할 수 있다.
- 사용자 폴더 삭제는 확인 대화상자를 거친다.
- 폴더를 삭제하면 그 폴더의 북마크 연결도 함께 제거한다.
- 기본 폴더 삭제는 거부한다.

폴더 목록은 이름, 포함 정책 수 또는 고정 상태 같은 화면 정렬 기준으로 볼 수
있지만 저장 identity는 정렬에 따라 바뀌지 않는다.

## 공개 정책과의 연결

즐겨찾기는 정책 ID만 로컬에 보존한다. 공개 dataset 교체 뒤 해당 정책이 inactive,
종료일 경과 또는 membership 밖이 되면 공개 API가 더 이상 상세를 반환하지 않을
수 있다. 이 경우 저장 ID가 남아 있어도 비공개 정책을 우회해 표시하지 않는다.

즐겨찾기는 Backend의 정책 FK나 관리자 DB row를 직접 만들지 않는다. 따라서 DB
초기화와 브라우저 데이터 초기화는 서로 다른 작업이다.

## D-Day 계산 원리

D-Day는 정규화된 신청 종료일과 한국 표준시의 오늘 날짜 차이로 계산한다.

| 조건 | 표시 |
| --- | --- |
| 종료일까지 하루 이상 | `D-n` |
| 오늘 종료 | `D-Day` |
| 종료일 경과 | 표시하지 않음 |
| 종료일 `null`·해석 실패 | 표시하지 않음 |
| 명시적 마감 상태 | 표시하지 않음 |

브라우저의 임의 timezone 문자열 대신 `Asia/Seoul` 날짜를 사용해 자정 주변의
D-Day 오차를 줄인다.

## 달력 원리

달력은 즐겨찾기 정책의 신청 시작일과 종료일에서 일정 event를 계산한다.

- 월 단위 6주 grid를 사용한다.
- 한 정책은 시작 event와 종료 event를 각각 가질 수 있다.
- 시작일이나 종료일이 없는 경우 해당 event만 만들지 않는다.
- 날짜별 event를 묶고 정책 상세로 이동할 수 있다.
- 월 이동과 키보드 focus 날짜를 분리해 탐색을 유지한다.

달력은 외부 일정 서비스가 아니라 브라우저 안에서 계산한 보기다. Google
Calendar, Apple Calendar나 Microsoft Outlook 계정 권한을 요청하지 않는다.

## `.ics` 다운로드

종료일이 확인된 정책은 RFC 5545 VEVENT 형식의 all-day `.ics` 파일로 만들 수
있다. 정책 제목, 날짜, 설명과 안전한 공식 URL의 특수문자를 escape한다.

다운로드 이후 파일을 어느 앱에 추가할지는 사용자가 결정한다. 서비스는 외부
캘린더에 일정을 생성하거나 이후 날짜 변경을 자동 동기화하지 않는다.

## 알림 원리

알림 화면은 즐겨찾기 ID와 현재 공개 정책을 교차해 마감이 가까운 정책을 찾는다.
현재 기준은 마감일이 확인되고 지정된 임박 범위 안에 있는 정책이다.

다음 정책은 알림에서 제외한다.

- 즐겨찾기에 없는 정책
- 마감일이 없거나 해석되지 않은 정책
- 이미 마감된 정책
- 현재 공개 API에서 조회되지 않는 정책

알림은 화면을 열었을 때 계산하는 내부 알림이다. 운영체제 push, 브라우저 push,
이메일과 SMS를 전송하지 않는다.

## 사용자 데이터 Schema와 복구

프로필, 폴더와 북마크는 하나의 versioned 사용자 저장 구조를 공유한다. 지원하는
이전 단일 즐겨찾기 형식은 기본 폴더 기반 구조로 이동한다.

JSON 손상, 지원하지 않는 Schema version 또는 저장 실패에서는 애플리케이션이
중단되지 않도록 안전한 기본값을 사용하고 복구 안내를 제공한다. 복구 과정에서
서버나 외부 서비스에 데이터를 전송하지 않는다.

## 전체 사용자 데이터 초기화

사용자 데이터 초기화는 현재 브라우저의 프로젝트 storage key만 지운다.
PostgreSQL 정책, 공개 dataset, 관리자 PIN과 CollectionRun에는 영향을 주지 않는다.
삭제된 브라우저 데이터는 서버 백업이 없어 복구할 수 없다.

## 접근성과 오류 상태

- 즐겨찾기 버튼은 현재 저장 여부를 접근 가능한 이름으로 제공한다.
- 폴더 메뉴는 바깥 클릭과 Escape로 닫힌다.
- 삭제 확인은 대상 폴더를 명시한다.
- 정책 조회 실패와 즐겨찾기 없음 상태를 구분한다.
- 날짜가 없으면 잘못된 일정이나 D-Day를 만들지 않는다.

## 현재 제한사항

- 다른 PC·브라우저와 동기화하지 않는다.
- 브라우저 데이터 삭제·비공개 모드 종료 뒤 복구할 서버 사본이 없다.
- 알림은 background 전송 기능이 아니다.
- `.ics` 파일은 snapshot이며 공식 일정 변경을 추적하지 않는다.
- 공개 dataset에서 빠진 정책은 저장 ID만으로 계속 열 수 없다.
