# 정책 상세와 자격정보

## 기능 목적

검색·추천에서 발견한 정책의 실제 신청 조건, 혜택과 공식 원문을 한 화면에서
검토하게 한다. 정보가 없는 상태를 임의로 채우지 않고, 확인된 사실과 추가 확인이
필요한 조건을 구분하는 것이 핵심 원칙이다.

## 사용하는 화면

- 주소: `/programs/{id}`
- 진입: 홈 추천, 정책 목록, 검색 결과, 맞춤 추천, 즐겨찾기, 달력과 알림

모든 진입점은 같은 공개 정책의 숫자 DB ID를 사용한다. 검색에서 `partial` 정책을
선택했으면 상세 조회에도 명시적인 partial 허용 상태를 전달한다.

## 상세정보 구성

정책별 원문 범위에 따라 다음 정보를 보여준다.

- 제목, 주관기관과 데이터 Source
- 신청 상태와 신청 시작·종료일
- 대상 지역과 연령
- 전체 정책 분야
- 핵심 지원 대상과 자격 조건
- 필수·우대·제외 조건
- 지원 내용과 혜택
- 신청 방법과 제출 서류
- 기관 문의처
- 수집·검증 상태
- 공식 신청·공고 사이트

목록과 상세은 같은 정규화 정책 row를 사용하므로 제목, 기간, 지역과 분야의
의미가 서로 달라지지 않아야 한다.

## 자격정보의 원리

Source마다 자격 조건의 구조가 다르기 때문에 원문을 바로 자격 판정문으로 쓰지
않는다. 수집 파이프라인은 조건을 evidence와 summary로 나눈다.

```text
공식 원문
→ Source별 조건 추출
→ 조건 category와 근거 위치 기록
→ 공통 Eligibility Summary
→ 사용자용 핵심 조건과 미확정 안내
```

Eligibility Summary는 연령, 지역, 소득·자산, 학력, 취업 상태, 가구와 기타
조건을 공통 의미로 표현한다. 제출 서류와 기관 연락처도 원문에서 확인한 근거만
사용한다.

## 확인 상태 구분

상세 화면은 다음 상태를 같은 의미로 취급하지 않는다.

| 상태 | 의미 | 표시 원칙 |
| --- | --- | --- |
| 확인됨 | 원문에서 조건과 값을 확인 | 구조화 값과 설명 표시 |
| 제한 없음 | 원문이 해당 제한이 없음을 명시 | `제한 없음`으로 표시 |
| 원문 값 비어 있음 | 라벨은 있으나 값이 비어 있음 | 비어 있음을 보존 |
| 찾지 못함 | 현재 수집 계약이 라벨·값을 확인하지 못함 | `미확인` 또는 원문 확인 안내 |
| 해석 불가 | 원문은 있으나 안전한 공통값으로 변환 불가 | 원문 의미와 미확정 상태 유지 |

`찾지 못함`을 `제한 없음`으로 바꾸지 않는다. `0세~0세` 같은 Source placeholder도
실제 연령 제한으로 표시하지 않는다.

## 미확정 정보

소득, 자산, 재직, 학력, 가구 구성처럼 자동 판정에 필요한 정보가 충분하지
않으면 미확정 조건으로 분리한다. 미확정은 신청 불가를 뜻하지 않으며, 사용자가
공식 원문에서 추가로 확인해야 한다는 의미다.

검색·추천 응답의 `unknown_conditions`와 상세 Eligibility Summary는 같은
비단정 원칙을 사용한다. 화면은 정책 후보를 안내할 뿐 실제 자격 충족을 선언하지
않는다.

## 날짜와 D-Day

신청 기간은 Source별 텍스트·날짜 형식을 정규화한 시작일과 종료일을 사용한다.
D-Day는 종료일이 확인되고 모집 상태가 유효할 때만 한국 표준시 기준으로 계산한다.

- 마감일까지 남은 날: `D-n`
- 오늘 마감: `D-Day`
- 종료일 경과, 날짜 미확정 또는 마감 상태: D-Day 없음

상시 모집과 날짜 미정은 서로 다른 신청 일정 상태로 보존한다.

## 공식 원문 연결

공식 사이트 버튼은 정책에 검증된 HTTP(S) Source URL이 있을 때만 활성화한다.
링크는 새 창에서 공식 기관의 최신 공고를 확인하기 위한 경로다.

서비스가 보여주는 신청 기간과 상태는 마지막 공개 dataset의 snapshot이므로
사용자는 원문에서 다음을 다시 확인해야 한다.

- 모집이 아직 진행 중인지
- 지역·연령·소득 등 세부 조건
- 제출 서류와 접수 방법
- 예산 소진, 조기 마감과 추가 공지

## 즐겨찾기와 일정 파일

상세 화면에서 정책을 현재 브라우저의 즐겨찾기 폴더에 추가·제거할 수 있다.
종료일이 확인된 정책은 RFC 5545 형식의 `.ics` all-day 일정을 내려받을 수 있다.
파일에는 정책명, 날짜와 안전한 원문 URL을 사용하며 외부 캘린더 계정으로 직접
전송하지 않는다.

## 공개·보안 경계

일반 상세 API는 활성 공개 dataset membership에 포함된 정책만 반환한다.

- membership 밖 정책: `404`
- inactive 또는 종료일 경과 정책: 공개 상세 `404`
- `invalid` 정책: 공개하지 않음
- `partial` 정책: 명시적 허용 조건에서만 조회

Raw API/XML/HTML payload, 비밀 query, 내부 DB 생명주기 필드와 관리자 전용
provenance는 일반 상세 응답에 포함하지 않는다.

## 빈 값과 오류

- 존재하지 않거나 비공개인 ID는 같은 안전한 not-found 흐름을 사용한다.
- 일시적 API 오류는 not-found와 구분해 재시도 가능한 오류로 안내한다.
- 연락처가 개인 휴대전화·이메일 안전 경계를 통과하지 못하면 공개 dataset row
  전체가 제외될 수 있다.
- 기관 문의처가 없으면 임의의 전화번호나 대표번호를 추정하지 않는다.

## 현재 제한사항

- Source가 제공하지 않은 조건은 서비스가 새로 만들어 낼 수 없다.
- 정규화된 요약은 공식 공고 전체를 대체하지 않는다.
- 원문이 바뀌어도 새 dataset이 승격되기 전까지 상세 snapshot은 갱신되지 않는다.
- `.ics`는 다운로드 기능이며 일정 변경을 자동 추적하지 않는다.
