# 청년정책알리미 기능 설명서

## 문서 정보

- 대상: 일반 사용자, 대회 심사자, 서비스 관리자, 중앙 데이터 운영자
- 기준: `v1.0.2` 공개 기능과 `Unreleased` 관리자 PIN·수집기 운영 개선
- 확인일: 2026-08-26
- 목적: 현재 구현되어 실제로 사용할 수 있는 기능과 동작 경계를 한 문서에서 설명

이 문서는 개발 계획이 아니라 현재 제품 기능을 설명한다. API의 정확한 필드와
상태 코드는 `docs/api/`, 데이터 판정 규칙은 `docs/data/`, 설치·복구 절차는
`docs/operations/` 문서를 권위 계약으로 사용한다.

## 1. 서비스 개요

청년정책알리미는 여러 공공기관의 청년정책을 공통 형식으로 정리해 지역, 연령,
관심 분야와 검색어에 맞는 정책을 찾고 비교할 수 있게 하는 오픈소스 웹
프로그램이다.

일반 사용자는 별도 회원가입 없이 정책 검색, 맞춤 추천, 즐겨찾기, 마감 알림과
달력을 사용할 수 있다. 관리자는 수집 실행과 데이터 품질을 확인하며, 중앙 데이터
운영자는 검증된 새 공개 dataset을 만들어 배포한다.

```text
공식 정책 Source
→ 중앙 수집·정규화·품질 검증
→ versioned 공개 dataset
→ 사용자 PC의 PostgreSQL
→ 검색·추천 API
→ 사용자·관리자 Web UI
```

일반 사용자의 PC가 온통청년이나 복지로 API를 직접 반복 호출하지 않는다.
`run_docker.bat`이 검증된 공개 dataset을 설치하므로 API key 없이 동일한 정책
집합을 사용할 수 있다.

## 2. 사용자 화면과 주소

| 화면 | 주소 | 주요 용도 |
| --- | --- | --- |
| 홈 | `/` | 자연어 검색 시작, 예시 검색, 프로필 기반 추천 확인 |
| 정책 목록 | `/programs` | 검색 결과, 필터, 정렬, 페이지 이동 |
| 정책 상세 | `/programs/{id}` | 신청 조건·혜택·기간·공식 원문 확인 |
| 맞춤 추천 | `/recommendations` | 지역·연령·복수 관심 분야 기반 추천 |
| 즐겨찾기 | `/favorites` | 저장한 정책과 폴더 관리 |
| 달력 | `/calendar` | 즐겨찾기 정책의 시작일·마감일 확인 |
| 알림 | `/notifications` | 즐겨찾기 정책의 임박 마감 확인 |
| 프로필 | `/profile` | 거주지역·연령·복수 관심 분야 저장 |
| 관리자 로그인 | `/admin/login` | 4자리 관리자 PIN 로그인 |

`/search`는 이전 검색 진입 주소와의 호환을 위한 경로이며 현재 정책 목록 화면으로
연결된다.

## 3. 홈과 자연어 정책 검색

### 3.1 검색 시작

홈 검색창에 정책명, 대상, 지역, 분야를 자연어로 입력할 수 있다. 검색어와 함께
시·도, 시·군·구, 연령과 관심 분야를 명시적으로 선택할 수도 있다.

예시 검색어는 실제 결과가 존재하는 검색 조건으로 연결된다. 넓거나 다른 표현으로
검색했을 때는 사용자가 선택할 수 있는 관련 검색어를 함께 제공한다. 관련 검색어는
자격을 임의로 확장하거나 사용자가 입력한 검색어를 자동으로 바꾸지 않는다.

### 3.2 지역 검색

시·군·구를 선택하면 다음 범위를 함께 탐색한다.

- 선택한 시·군·구 대상 정책
- 그 시·군·구가 속한 상위 시·도 대상 정책
- 전국 대상 정책

예를 들어 양산시를 선택하면 양산시, 경상남도와 전국 정책을 후보로 평가한다.
지역 근거가 비어 있거나 해석되지 않은 정책은 전국 정책으로 추정하지 않고
`지역 일치 미확인` 상태로 구분한다.

### 3.3 홈 추천

저장된 프로필 조건이 있으면 홈의 추천 영역이 맞춤 추천 API를 사용한다. 프로필이
없으면 현재 신청 가능한 정책 중 마감·접수 예정·지난 마감일을 제외한 정책을
보수적인 기본 후보로 보여준다.

## 4. 정책 목록·검색 결과

### 4.1 검색 조건

정책 목록에서는 다음 조건을 조합할 수 있다.

- 검색어
- 시·도와 시·군·구
- 연령
- 관심 분야
- 신청 상태
- partial 품질 정책 포함 여부

검색어에서 해석한 조건과 사용자가 직접 선택한 필터는 화면에 구분해 표시한다.
해석하지 못한 표현은 조용히 버리지 않고 안내 대상으로 남긴다.

### 4.2 관심 분야

정책은 고용, 주거, 교육, 복지, 금융 등 여러 분야에 동시에 속할 수 있다.
목록·검색·추천·상세는 대표 분야 하나만 보여주지 않고 정책의 전체 분야를
표시한다. 분야 필터는 정책의 전체 분야 중 하나라도 일치하면 후보로 평가한다.

### 4.3 정렬과 페이지 이동

검색 결과는 다음 기준으로 정렬할 수 있다.

- 관련도순
- 가나다순
- 마감일순
- 최근 수집순

동일한 조건에서는 결과 순서가 바뀌지 않도록 결정적 보조 정렬을 적용한다.
페이지를 이동해도 현재 검색어와 필터, 정렬 조건을 URL에 유지한다.

### 4.4 결과 카드

정책 카드에서는 제목, 주관기관, 지역, 연령, 분야, 신청 상태, 신청 기간,
데이터 품질과 D-Day를 확인할 수 있다. 종료일이 없거나 해석되지 않은 정책에는
임의의 D-Day를 만들지 않는다.

검색 결과는 신청 가능한 정책 후보를 안내하는 것이며 실제 자격 충족을 확정하지
않는다. 상세 조건과 최신 공고는 반드시 공식 원문에서 확인해야 한다.

## 5. 정책 상세

정책 상세에서는 가능한 범위에서 다음 정보를 제공한다.

- 정책명과 주관기관
- 현재 신청 상태와 신청 기간
- 대상 지역과 연령
- 전체 관심 분야
- 핵심 지원 대상과 자격 조건
- 제외 조건과 우대 조건
- 지원 내용과 혜택
- 신청 방법과 제출 서류
- 기관 문의처
- 데이터 출처와 수집 시각
- 공식 신청·공고 사이트 링크

원문에 조건이 없다는 사실과 현재 데이터가 조건을 찾지 못한 상태는 서로 다르게
표시한다. 자동으로 확정할 수 없는 소득, 자산, 재직, 학력 등의 조건은 미확정
정보로 안내한다.

공식 사이트 버튼은 저장된 안전한 HTTP(S) 원문 주소가 있을 때만 제공한다.
사용자는 공식 원문에서 최신 모집 상태, 세부 자격과 실제 접수 방법을 다시
확인해야 한다.

마감일이 확인된 정책은 `.ics` 일정 파일을 내려받을 수 있다. 내려받은 파일은
사용자가 선택한 캘린더 프로그램에 직접 추가하는 방식이며 외부 캘린더 계정을
서비스에 연결하지 않는다.

## 6. 맞춤 추천

맞춤 추천은 거주지역, 만 연령, 복수 관심 분야와 신청 상태를 사용한다. 정책의
분야, 지역, 연령과 신청 상태를 결정적 규칙으로 평가하며 선택한 지역의 하위·상위
관할과 전국 범위를 고려한다. 복수 관심 분야는 하나 이상 일치하는 정책을 후보로
평가한다.

각 추천 결과에는 가능한 범위에서 다음 설명을 제공한다.

- 어떤 지역 조건이 일치했는지
- 연령 조건이 일치했는지
- 어떤 관심 분야가 일치했는지
- 현재 신청 가능한 상태인지
- 자동 확인할 수 없어 원문 확인이 필요한 조건

추천 점수는 정책 탐색을 돕기 위한 우선순위이지 신청 자격이나 선정 가능성의
확률이 아니다. 확정 불일치 조건은 후보에서 제외하지만, 근거가 부족한 조건은
불일치로 단정하지 않고 미확정으로 표시한다.

## 7. 프로필

프로필 화면에서 거주지역, 만 연령과 여러 관심 분야를 저장할 수 있다. 저장한
프로필은 홈 추천과 맞춤 추천에 사용되고, 자연어 검색에서는 사용자가 입력한
검색 조건을 덮지 않은 채 관련도 우선순위만 보정한다.

프로필에는 이름, 주민등록번호, 전화번호나 이메일을 입력하지 않는다. 프로필은
현재 브라우저의 `localStorage`에만 저장되며 서버 계정이나 다른 PC·브라우저와
동기화되지 않는다.

브라우저 저장 데이터가 손상됐거나 지원하지 않는 이전 형식이면 안전한 기본값으로
복구하고 사용자에게 복구 사실을 알린다.

## 8. 즐겨찾기

정책 카드와 상세 화면에서 정책을 즐겨찾기에 추가하거나 제거할 수 있다.
즐겨찾기 화면에서는 기본 폴더와 사용자가 만든 폴더로 정책을 나눠 관리할 수 있다.

- 기본 폴더는 삭제할 수 없다.
- 사용자 폴더를 삭제할 때는 확인 절차를 거친다.
- 정책과 폴더 정보는 현재 브라우저에만 저장된다.
- Backend DB에 사용자 계정이나 즐겨찾기 기록을 저장하지 않는다.

공개 dataset이 교체돼 기존 정책이 더 이상 공개되지 않으면 저장된 ID가 남아
있더라도 해당 정책의 공개 상세를 표시하지 못할 수 있다.

## 9. D-Day·달력·알림

### 9.1 D-Day

신청 종료일이 확인된 모집 중 정책은 한국 표준시 기준으로 `D-n` 또는
`D-Day`를 표시한다. 종료일이 지났거나 날짜가 미확정이면 잘못된 D-Day를 만들지
않는다.

### 9.2 달력

달력은 즐겨찾기에 저장된 정책의 신청 시작일과 종료일을 월 단위로 보여준다.
날짜를 선택하면 해당 날짜의 정책을 확인할 수 있다. 이 달력은 서비스 내부
화면이며 Google Calendar, Apple Calendar 같은 외부 계정과 자동 동기화하지
않는다.

### 9.3 알림

알림 화면은 즐겨찾기 정책 중 마감이 가까운 정책을 찾아 보여준다. 현재 알림은
웹 프로그램 내부 확인 기능이며 운영체제 push, 이메일, 문자 메시지를 발송하지
않는다.

## 10. 사용자 데이터와 개인정보 경계

일반 사용자 기능에는 회원가입과 서버 계정이 없다.

| 데이터 | 저장 위치 | 외부 전송 |
| --- | --- | --- |
| 프로필 지역·연령·관심 분야 | 현재 브라우저 `localStorage` | 검색·추천 요청 시 로컬 Backend에 전달 |
| 즐겨찾기·폴더 | 현재 브라우저 `localStorage` | 외부 정책 Source에 전달하지 않음 |
| 캘린더 표시 | 즐겨찾기와 정책 날짜에서 즉시 계산 | 자동 외부 동기화 없음 |
| 관리자 세션 token | 브라우저 메모리 | 로컬 Backend 관리자 API에만 전달 |

브라우저 데이터를 삭제하거나 다른 브라우저·PC를 사용하면 프로필과 즐겨찾기는
자동으로 옮겨지지 않는다.

## 11. 관리자 기능

관리자 화면은 정책 검색 사용자와 다른 운영 목적의 화면이다. `/admin` 아래
모든 화면은 유효한 관리자 세션이 없으면 로그인 화면으로 이동한다.

### 11.1 로그인·세션·로그아웃

- 최초 Docker 실행 때 관리자가 설정한 숫자 4자리 PIN을 사용한다.
- PIN 평문은 저장하지 않고 salted verifier로 검증한다.
- 로그인 실패가 반복되면 점진적 잠금 시간을 적용한다.
- 관리자 access token은 브라우저 메모리에만 유지한다.
- 새로고침, 명시적 로그아웃, 세션 만료 또는 PIN 변경 시 다시 로그인해야 할 수
  있다.
- URL, 로그와 영구 `localStorage`에 PIN이나 access token을 기록하지 않는다.

### 11.2 관리자 보안

`/admin/security`에서 현재 PIN을 확인한 뒤 새 4자리 PIN으로 변경할 수 있다.
PIN 변경에 성공하면 기존 관리자 세션을 모두 무효화하고 로그인 화면으로
이동한다.

현재 PIN을 잊은 경우 서버 PC의 저장소 루트에서 `reset_admin_pin.bat`을
실행한다. 이 복구는 관리자 인증 상태만 갱신하며 정책 DB, 공개 dataset,
CollectionRun과 Docker Volume을 보존한다.

### 11.3 대시보드

`/admin` 대시보드는 가장 최근 CollectionRun의 상태, source, 실행 방식,
시작·종료 시각과 주요 품질 집계를 보여준다. 실패나 부분 실패가 있으면 실행
상세와 구조화 로그로 이동할 수 있다.

### 11.4 수집기 운영 상태

`/admin/collectors`는 현재 등록된 11개 수집기를 보여준다.

- source ID와 표시명
- API, 공개 파일, 공식 웹 유형
- Redis broker와 Celery worker 연결 상태
- worker 등록 여부
- 필요한 인증정보의 설정됨·미설정 상태
- 자동 수집 스케줄 활성 여부와 실행 시각
- 활성 공개 dataset에 포함된 source별 정책 수
- 현재 실행과 최근 CollectionRun
- 실행 가능한 source의 관리자 수동 실행

API key 값, 일부 문자열, 길이와 worker hostname은 화면에 노출하지 않는다.
인증정보 상태는 중앙에서 새 데이터를 수집할 준비 여부이며, 이미 설치된 공개
dataset을 검색할 수 있는지와는 별개다.

### 11.5 CollectionRun

`/admin/runs`는 환경에서 발생한 dataset Seed import, Runtime import와 수집 실행
기록을 조회한다.

- source, 상태, 실행 유형, trigger, 기간 필터
- 페이지 이동
- 시작·종료 시각과 삽입·갱신·실패 건수
- 실행 ID별 상세 집계
- 대기·실행 상태가 기준 시간을 넘긴 stale 표시
- source별 수동 실행과 중복 실행 방지

CollectionRun은 해당 PC의 로컬 감사 기록이므로 작성자와 심사자의 실행 건수가
같을 필요는 없다. 사용자에게 공개되는 정책의 동등성은 CollectionRun 개수가
아니라 활성 dataset version과 identity hash로 판단한다.

수동 수집은 외부 Source 호출과 DB 변경을 만들 수 있으므로 확인 대화상자를
거친다. 수동 실행 결과는 공개 dataset 검증·승격 전까지 일반 사용자 검색에
자동으로 포함되지 않는다.

### 11.6 데이터 품질

`/admin/quality`는 최근 CollectionRun별 실패, 무효, 중복 등 품질 지표를 비교하고
관련 실행 상세로 이동할 수 있게 한다. 집계는 데이터 문제를 찾기 위한 운영
정보이며 사용자 신청 자격을 나타내지 않는다.

### 11.7 정책 데이터 관리

`/admin/policies`는 PostgreSQL 정책을 읽기 전용 표로 조회한다.

- 정책 ID, source와 external ID
- 제목과 기관
- 분야와 지역
- 데이터 품질 상태
- 수집·생성·갱신·검증·비활성 시각
- allowlist 컬럼 정렬과 페이지 이동
- 행별 상세 확인

화면은 원본 payload, SQL parameter, API key와 비밀정보를 제공하지 않는다.
현재 기능은 조회 전용이며 화면에서 정책을 직접 편집하거나 삭제하지 않는다.

### 11.8 구조화 로그

`/admin/logs`는 Backend가 허용한 구조화 로그 파일과 안전한 이벤트 필드만
조회한다. level, component, event, request ID, CollectionRun ID, source,
처리 시간과 오류 유형을 확인할 수 있다.

활성 로그는 실행 중 삭제할 수 없다. 보관 archive 정리는 확인 절차와 감사
기록을 남기며, stack trace, request·response body, SQL parameter, 파일 절대
경로와 비밀정보는 API 응답에서 제외한다.

## 12. 정책 데이터와 공개 범위

### 12.1 현재 공개 dataset

2026-08-25에 확인한 `v1.0.2` 공개 dataset은 총 2,052건이다.

| Source | 정책 수 |
| --- | ---: |
| 복지로 중앙부처 복지서비스 | 461건 |
| 온통청년 청년정책 API | 1,587건 |
| 인천광역시 청년공간 유유기지 공개 파일 | 4건 |
| 합계 | 2,052건 |

이 수치는 `public-bootstrap-20260824-897152e7a18c15` snapshot 기준이다. 이후
새 dataset이 승격되면 latest manifest의 version, 정책 수와 SHA-256을 우선한다.

### 12.2 공개 dataset과 로컬 DB

DB에는 로컬 개발 수집, 과거 실행과 공개하지 않은 정책이 함께 남을 수 있다.
일반 목록·검색·추천·상세 API는 활성 공개 dataset membership에 포함된 정책만
조회한다.

- 공개 dataset 밖의 기존 정책을 물리적으로 삭제하지 않는다.
- 즐겨찾기 등 기존 정책 참조를 보존한다.
- 새 dataset 검증이 실패하면 이전 활성 version을 유지한다.
- 수동 수집 결과는 별도 승격 전까지 미공개 상태다.
- 같은 dataset version을 설치한 환경은 같은 공개 정책 identity 집합을 반환해야
  한다.

### 12.3 데이터 품질 표시

정책은 완전히 확인된 `valid`와 일부 조건 확인이 필요한 `partial` 상태를 가질 수
있다. `partial`은 오류 정책이라는 뜻이 아니라 원문에서 일부 조건을 자동으로
확정할 수 없음을 의미한다. 화면은 확인되지 않은 값을 임의로 채우지 않고
미확정 안내와 원문 확인 경로를 제공한다.

종료일이 지난 정책과 inactive 정책은 기본 공개 검색·추천에서 제외한다. 날짜는
한국 표준시 기준으로 판단한다.

## 13. 데이터 수집과 배포

중앙 운영 환경은 공식 API, 공개 파일과 허용된 공식 웹 source를 수집한다.
등록된 수집기 수와 공개 dataset source 수는 같지 않다. 수집이 기술적으로
가능해도 재배포 근거가 확인되지 않은 source는 공개 artifact에서 제외한다.

수집 데이터는 다음 단계를 통과한다.

1. 원문 수집과 출처 기록
2. source별 필드 추출
3. 날짜·지역·연령·분야 공통 형식 정규화
4. Schema·품질·중복·생명주기 검증
5. 공개 허용 source와 필드만 dataset 후보로 선택
6. 개인정보·비밀 pattern과 row·hash 검증
7. 격리 DB 설치 및 공개 projection parity 확인
8. versioned artifact 발행과 latest pointer 승격

실패·부분 수집, row 수 불일치, hash 불일치와 지역 coverage 부족에서는 직전 공개
dataset을 유지한다. 실제 Raw payload, PostgreSQL dump, API key와 비밀 query는
GitHub Release에 포함하지 않는다.

## 14. 로딩·빈 결과·오류 처리

- API 요청 중에는 해당 화면의 로딩 상태를 표시한다.
- 검색·추천 결과가 없으면 오류 화면 대신 조건에 맞는 결과가 없음을 안내한다.
- 네트워크·서버 오류는 재시도 가능한 오류와 입력 검증 오류를 구분한다.
- 관리자 인증이 만료되면 세션을 지우고 로그인 화면으로 이동한다.
- 정책 상세가 없거나 공개 범위 밖이면 안전한 not-found 상태를 표시한다.
- partial과 미확정 정보는 정상 확정 정보와 시각·문구로 구분한다.

## 15. 접근성과 반응형

주요 화면은 키보드로 이동할 수 있도록 링크, 버튼, form label과 focus 상태를
제공한다. 상태 badge는 색상만으로 의미를 전달하지 않고 텍스트를 함께 표시한다.
대화상자는 역할과 제목을 연결하고 Escape로 닫을 수 있다.

모바일·좁은 화면에서는 카드와 요약 영역을 한 열로 재배치한다. 넓은 관리자 표는
내용을 임의로 잘라내는 대신 필요한 경우 표 영역 안에서 가로 이동할 수 있게 한다.

## 16. 현재 제한사항

- 일반 사용자 계정, 서버 기반 프로필·즐겨찾기 동기화는 제공하지 않는다.
- 프로필과 즐겨찾기는 브라우저 데이터를 삭제하면 복구할 수 없다.
- 알림은 웹 내부 기능이며 push·이메일·SMS를 발송하지 않는다.
- 외부 캘린더 계정과 자동 동기화하지 않고 `.ics` 파일만 제공한다.
- 추천과 검색 결과는 신청 자격 또는 선정 가능성을 확정하지 않는다.
- 공식 Source의 변경이 공개 dataset에 실시간 반영되지는 않는다. 중앙 검증과 새
  dataset 승격이 필요하다.
- 관리자의 수동 수집 결과도 즉시 일반 사용자에게 공개되지 않는다.
- CollectionRun과 로컬 수집 정책 수는 환경마다 다를 수 있다.
- one-command clean-room 실행은 현재 Windows 10/11과 Docker Desktop을 기준으로
  검증됐다.
