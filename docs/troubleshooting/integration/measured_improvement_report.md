# 실측 기반 문제 해결·개선율 보고서

## 보고 목적

Data·Team Leader 작업에서 실제로 발생한 큰 문제를 해결한 뒤, 같은 분모 또는
같은 실행 조건으로 비교할 수 있는 결과를 개선율로 요약한다. 이 문서의 수치는
각 문제 해결 기록과 완료된 개발 기록에서 확인할 수 있는 전·후 값만 사용한다.

단순 테스트 건수 증가, 서로 다른 범위의 실행 결과와 추정값은 개선율에 포함하지
않는다. 퍼센트는 문제 해결 효과를 빠르게 전달하기 위한 요약이며, 원인·해결
과정·검증 조건은 연결된 개별 트러블슈팅 문서를 기준으로 한다.

## 1. 추천 전체 정책 판정 성능

정확성을 위해 승인된 정책 3,273건 전체를 평가하자 정책마다 지역 rule과 catalog를
다시 조회하는 N+1이 드러났다. 지역 근거를 bulk 조회하고 메모리에서 결정적으로
판정하도록 바꾼 결과는 다음과 같다.

```text
응답시간 감소율 = (14,845 - 1,386) / 14,845 × 100 = 90.66%
속도 배율       = 14,845 / 1,386 = 10.71배
```

- 응답시간: 약 14.8초에서 약 1.4초로 **90.7% 감소**
- 단축 시간: 약 13.5초
- 속도: 약 **10.7배 향상**
- 정확성: 대구 조건 34건 전부 지역 `match`, `closed` 0건

이는 같은 PC·DB·입력 조건에서 측정한 수정 전후 단일 관찰값이다. 반복 부하
시험의 평균, 운영 SLA 또는 모든 입력의 대표값으로 확대 해석하지 않는다.

상세 원인과 검증 조건은
[추천 전체 정책 판정의 N+1과 오추천 해결](../backend/recommendation_full_inventory_performance.md)에
기록돼 있다.

## 2. 연령 placeholder 오판 제거

온통청년 완료 snapshot 2,698건 중 631건은 근거 없는 `0세~0세` placeholder가
실제 연령 제한처럼 구조화돼 있었다. 원문은 보존하고 확인할 수 없는 숫자 bound를
해제한 뒤 실제 DB에 멱등 재적재했다.

```text
식별 오류 제거율 = (631 - 0) / 631 × 100 = 100%
전체 Source 영향률 = 631 / 2,698 × 100 = 23.39%
```

- 식별된 placeholder 오류: 631건에서 0건으로 **100% 제거**
- 온통청년 데이터 중 정상화 대상 비율: **23.4%**
- 첫 재적재: `updated 631`, 실패 0
- 동일 snapshot 재실행: `unchanged 2,698`

이 수치는 연령 데이터 전체 정확도가 100%가 됐다는 의미가 아니다. 식별한 특정
placeholder 오류를 전부 제거하고, 근거 없는 확정 mismatch를 `unknown`으로
되돌렸다는 의미다.

상세 내용은
[연령 `0세~0세` placeholder 오판 보정](../data/release_age_placeholder_normalization.md)에
기록돼 있다.

## 3. 지역 field evidence 미확인 상태 해소

지역 review 정책의 11,430개 field slot 중 과거 수집기가 남긴
`null_unverifiable` 2,760개는 값이 없는 것인지, label을 찾지 못한 것인지조차
구분할 수 없었다. Source별 제한 재캡처와 명시 상태 분류를 적용했다.

```text
legacy 상태 해소율 = (2,760 - 0) / 2,760 × 100 = 100%
전체 field slot 영향률 = 2,760 / 11,430 × 100 = 24.15%
```

- legacy `null_unverifiable`: 2,760개에서 0개로 **100% 해소**
- 전체 field slot 중 명시 상태로 전환한 비율: **24.1%**
- RYP8 blocker: 1개에서 0개
- `data_ready`: `false`에서 `true`

원문에 없는 값을 생성한 것이 아니라 `value_extracted`,
`label_present_value_empty`, `label_not_found`처럼 실제 관찰 결과를 명시했다.
따라서 이 지표는 모든 결측값이 채워졌다는 의미가 아니다.

상세 내용은
[지역 Browser 수집 실패·drift 안전 복구](../data/regional_browser_capture_recovery.md)에
기록돼 있다.

## 4. 지역정책 증거 기반 재분류

RYP8과 RYP9는 같은 지역 identity 4,606건을 사용한다. field evidence 보강과
taxonomy·현재성·지역 Gate를 통과시킨 결과만 outcome을 변경했기 때문에 같은
분모로 개선율을 계산할 수 있다.

| outcome | RYP8 | RYP9 | 상대 변화율 | 전체 대비 비중 변화 |
| --- | ---: | ---: | ---: | ---: |
| accepted | 18 | 109 | **505.6% 증가** | 0.39% → 2.37%, **+1.98%p** |
| review | 1,905 | 1,140 | **40.2% 감소** | 41.36% → 24.75%, **-16.61%p** |
| closed | 2,360 | 3,033 | 28.5% 증가 | 51.24% → 65.85%, +14.61%p |
| failed | 322 | 322 | 0.0% | 6.99% → 6.99%, 0.00%p |

accepted는 기존 대비 약 **6.06배**가 됐고, review 765건을 줄였다. 다만 closed
증가는 정책 품질이 나빠졌다는 뜻이 아니라 과거 정책의 실행일 현재성을 확인해
종료 상태로 확정한 결과다. failed 322건은 검증하지 않은 성공으로 바꾸지 않고
그대로 보존했다.

`505.6% 증가`는 작은 최초 accepted 기준선 18건을 분모로 한 상대 변화율이다.
대외 보고에서는 전체 4,606건 중 accepted 비중이 `0.39% → 2.37%`로
**1.98%p 증가**했다는 값도 함께 제시해 규모를 오해하지 않게 한다.

## 5. Review admission 안전성 개선

지역 review 1,140건의 최초 admission manifest는 5건을 승격 후보로 잡았지만,
실행일 현재성 재판정에서 종료된 대구 정책 2건을 확인했다. 잘못 적용된 최초
5건은 제한 rollback한 뒤 최종 3건만 canonical region rule과 함께 적재했다.

```text
승격 후보 정제율 = (5 - 3) / 5 × 100 = 40.0%
review 판정 완료율 = (3 + 66) / 1,140 × 100 = 6.05%
```

- 승격 후보: 5건에서 3건으로 **40.0% 정제**
- 전체 review 중 판정 완료: 69건, **6.1%**
- 최종 승격: 3건, 전체 review의 0.26%
- 종료 확정: 66건, 전체 review의 5.8%
- 최종 승격 정책의 canonical region rule: 3/3, **100% 반영**

여기서 후보 감소는 생산성 저하가 아니라 오승격 방지 성과다. review 감소를
목표로 근거가 부족한 정책을 승격하지 않았고, 남은 1,071건은 `hold_review`로
보존했다.

상세 내용은
[Review admission 현재성·지역 projection 오적재 복구](../data/review_admission_currentness_recovery.md)에
기록돼 있다.

## 6. 서비스 정책 재고 변화

실제 중앙 정책 bootstrap 완료 기준선은 3,159건이고, 지역정책 적재와 review
admission까지 완료한 최종 서비스 DB는 3,273건이다. 두 시점 사이에는 여러
단계의 적재·중복 판정이 있으므로 개별 단계 건수를 단순 합산하지 않고 검증된
시점별 DB 총계만 비교한다.

```text
정책 재고 순증률 = (3,273 - 3,159) / 3,159 × 100 = 3.61%
```

최종 재고는 기준선보다 114건, **3.6% 증가**했다. 이는 데이터 품질 자체의
개선율이 아니라 검증을 통과해 서비스할 수 있게 된 정책 규모의 순변화다.

## 해석 원칙

### 개선율로 사용한 값

- 같은 입력·PC·DB 조건의 응답시간 전후 값
- 같은 Source snapshot에서 확인한 오류 건수 전후 값
- 같은 4,606개 identity의 outcome 전후 값
- 동일 review 1,140건의 admission 판정 결과

### 퍼센트로 과장하지 않는 값

- 테스트 수 증가는 구현 범위와 테스트 구성이 달라지므로 품질 개선율로 계산하지
  않는다.
- `passed`·`skipped` 비율은 같은 suite와 실행 조건이 아니면 전후 개선율로 쓰지
  않는다.
- `valid`·`partial` 구성비는 데이터 재고가 바뀌었으므로 정확도 개선율로 쓰지
  않는다.
- 단일 응답시간 측정은 부하 테스트 평균이나 운영 SLA로 표현하지 않는다.
- `0 → 3`처럼 기준값이 0인 변화에는 증가율을 계산하지 않고 최종 반영률만
  제시한다.

## 보고용 요약 문안

> 실제 정책 3,273건을 평가하는 추천 API의 지역 판정 N+1을 제거해 같은
> PC·DB·입력 조건에서 응답시간을 약 14.8초에서 1.4초로 90.7% 단축하고,
> 약 10.7배의 응답속도 개선을 확인했다.

> 온통청년 데이터 2,698건 중 631건(23.4%)에 존재한 연령 placeholder 오판을
> 정상화해 식별 오류를 100% 제거했으며, 지역정책 field slot의 미확인 legacy
> 상태 2,760개(24.1%)도 명시적 관찰 상태로 100% 전환했다.

> 동일한 지역정책 identity 4,606건을 증거 기반으로 재판정해 accepted를
> 18건에서 109건으로 505.6% 늘리고 review를 1,905건에서 1,140건으로 40.2%
> 줄였다. 미검증 failed 322건은 성공으로 과장하지 않고 그대로 보존했다.
